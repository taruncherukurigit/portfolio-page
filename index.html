Cherwood Network Solutions

The internal MSP division of Cherwood Corporation — building and operating the automation that manages, backs up, and secures every other Cherwood property, starting with Cherwood Health. Now extended into the ITSM process layer with a real ServiceNow integration. Full writeup, code, and the real troubleshooting story in the GitHub repo.

Python + Netmiko Git version control Drift detection LLDP topology discovery Flask dashboard cron ServiceNow ITSM

Root-caused a 12-year-old, still-open Paramiko/Cisco IOS bug

An unattended nightly system that backs up, version-controls, drift-checks, and maps the topology of three production devices — zero manual steps, built the way a real MSP scopes access into a client's environment. Real config drift now also opens a ServiceNow Incident automatically, with severity mapped from the diff content, and the same pipeline was verified against a full ServiceNow Change Request lifecycle — the process half of network operations, not just detection.

The real engineering story
BugRoot cause
Netmiko/Cisco IOS SSH failureLegacy IOS SSH servers don't follow RFC 4252's public-key handshake correctly — traced via debug-level Paramiko logs and a decade of open GitHub issues, fixed with a targeted compatibility patch rather than a workaround
False drift alerts, every runFortiGate re-encrypts password/key fields with a random salt on every pull — fixed with a normalization pass applied only to the drift-comparison copy
Site silently served the wrong contentReverse proxy connected over IPv6 loopback (::1) while the new nginx site only listened on IPv4 — traced by systematically ruling out DNS, Cloudflare cache, and tunnel config before finding the missing listen [::]:80; line
Same physical link counted as two edgesCisco and FortiGate each reported the other's hostname differently (short name vs. full FQDN) — fixed by normalizing every reported name against the canonical device inventory before deduplicating
A form field that silently refused to changeServiceNow's Normal Change model gates state transitions behind a real approval workflow and a required Assignment Group field, neither obvious from the form — fixed by working through genuine CAB-style approver records instead of fighting the state field

Cherwood Corporation · Division 02

Packetgeist

A passive 802.11 site survey of the Plainsboro Public Library — a three-storey, 46,500 sq ft public building — conducted with permission. Full RF analysis extracted directly from the survey database rather than read off a heatmap. Full write-up, raw data, and findings in the GitHub repo.

Passive 802.11 survey NetSpot Android SQLite extraction Channel planning Predictive model

The WiFi was fine. That was the finding.

Every measured location met the −67 dBm design threshold — no dead zones anywhere. The real problem was eight access points competing with each other for airtime on an unbalanced channel plan.
